# 安全管理平台研发实施需求说明

**用途：** 云效项目录入、研发实施拆分与验收沟通  
**适用范围：** 一期覆盖铸锻件分公司、智能加工配送中心；造型作业区作为当前原型示例  
**建设范围：** 目标职责、风险管理、巡检任务、隐患治理与督办、特殊作业管控、管理驾驶舱、移动现场端、培训记录与证书、安全知识库、应急管理、相关方管理

## 一、需求背景

安全生产业务目前以线下台账、Excel、纸质记录和分散审批为主。风险辨识、巡检、隐患整改、特殊作业等数据之间缺少统一关联：风险措施不能有效支撑巡检标准，巡检发现的问题难以持续跟踪整改，管理层也无法及时掌握各单位风险、隐患和作业状态。

平台建设目标是把安全管理从“分别登记、事后汇总”转为“过程留痕、状态可见、责任可追溯”。一期先在铸锻件分公司、智能加工配送中心落地，形成可复制的组织、权限、业务流程和数据标准，后续再推广至其他分子单位。

本期建设坚持“先跑通现场主线，再逐步丰富展示和分析”的原则。核心主线为：

```text
风险点建档与危险源评价
→ 风险点审批生效
→ 风险措施形成巡检标准
→ 巡检计划生成任务并现场执行
→ 不合格项转隐患
→ 受理、整改、复查、关闭与督办
→ 特殊作业风险分析、审批、监护、执行、归档
→ 驾驶舱汇总与管理下钻
```

## 二、产品目标

### 2.1 业务目标

1. 建立统一的安全业务入口，使组织、人员、岗位、角色和数据范围能够支撑各模块按权限办理业务。
2. 建立以风险点为核心的双重预防机制闭环：一个风险点可维护多个危险源，每个危险源分别完成事故类型、风险评价和五类管控措施，风险点整体审批后生效。
3. 建立巡检与隐患闭环：已生效风险措施可作为巡检标准依据；巡检不合格项可逐条或批量转为隐患，并完整保留发现、受理、整改、复查和关闭记录。
4. 建立特殊作业全过程管控：对动火、高处、临时用电、有限空间作业实施资格校验、风险分析、审批、监护、执行、延期和归档管理。
5. 为各级管理人员提供风险、隐患、督办、作业和履职数据的汇总、对比和下钻能力，并通过移动端和企业微信消息把待办送达现场人员。

### 2.2 产品边界

一期不建设完整培训中心、在线学习考试、设备设施管理、职业健康管理和原生移动 App。移动现场端采用响应式 H5/企业微信工作台；培训记录只读查询并由外部培训中心同步；安全知识库和应急管理以目录、原始文件查看与内容检索为主。相关方管理仅建设台账、人员证书、违章与三次违章自动黑名单标记，不建设公司资质、准入、评价、合同、门禁或黑名单限制。

## 三、衡量指标

以下指标作为研发实施验收的建议口径；性能并发和数据量阈值应在部署环境确定后补充为正式数值。

| 维度 | 指标 | 验收口径 |
|---|---|---|
| 范围覆盖 | 已确认的 11 个功能模块覆盖率 100% | 每个模块均具备约定页面、角色入口、关键操作与验收用例。 |
| 主线闭环 | 风险、巡检转隐患、特殊作业三条主线通过率 100% | 按业务角色从发起到最终状态完成演示，状态、意见、人员和时间留痕完整。 |
| 风险管理 | 风险点审批前校验覆盖率 100% | 每个危险源均须完成事故类型、评价和五类措施后，方可提交风险点整体审批。 |
| 巡检隐患 | 不合格项转隐患可追溯率 100% | 隐患可回查对应巡检任务、检查项、说明、照片、发现人和发现时间。 |
| 权限与留痕 | 关键操作留痕覆盖率 100% | 新增、提交、审核、退回、受理、分派、整改、复查、关闭、发布等动作均记录人员、时间、意见及前后状态。 |
| 组织人员同步 | 约定测试范围匹配率 100% | OA 同步的组织、部门、人员、岗位和在职状态可被平台正确引用；平台不回写 OA 主数据。 |
| 消息与待办 | 待办链路可用率 100% | PC、移动端与企业微信消息均可定位同一业务待办；消息投递失败不得改变业务状态。 |
| 数据质量 | 首批导入校验通过率 100% | 历史风险数据导入前完成必填项、事故类型、措施和版本校验；不合格数据须输出原因。 |

## 四、产品需求

### 4.1 共性需求

1. **组织与人员：** OA 是组织、部门、人员、岗位和在职状态的唯一来源。平台仅同步、查询和引用 OA 稳定标识，不允许手工维护 OA 主数据。
2. **角色与数据权限：** 平台根据 OA 人员标识配置安全业务角色、流程岗位和数据范围；组织基础角色决定可查看范围，业务流程岗位决定审批、领取、受理、整改、复查、监护等操作权限。
3. **审批：** 平台内审批统一调用系统内置 BPM 微服务，业务模块不自建审批路径、待办或状态机。集团监督检查为例外，跨系统委托 OA BPM，平台仅接收驳回起草人和最终结果。
4. **待办与消息：** 平台待办在 PC、移动端和企业微信消息中使用同一业务状态；企业微信仅承担移动入口和消息通知，不作为组织人员数据源。
5. **审计与编号：** 关键业务单据具备唯一编号、当前状态、操作日志、附件和历史记录；所有审核、审批、关闭、发布动作均应留痕。

### 4.2 功能需求

| 模块 | 核心需求 | 形成效果 |
|---|---|---|
| 目标职责 | 同步查看 OA 组织人员；维护平台用户、角色、角色数据权限、业务岗位映射和岗位安全职责清单。 | 建立统一的人员、角色和职责基础，避免以手工人员表驱动业务。 |
| 风险管理 | 风险点建档；一个风险点维护多个危险源；每个危险源填写一个或多个事故类型、LEC/直接判定、五类措施；按风险点整体进行 BPM 审批；支持变更复评、台账、四色图、在线告知卡和历史版本。 | 风险信息可分级、可审批、可追溯，并向巡检和特殊作业提供风险依据。 |
| 巡检任务管理 | 将生效风险措施关联为检查标准；创建计划并按周期生成任务；班组任务首人领取后锁定；现场逐项填写合格/不合格、说明和照片；未转隐患的不合格项可单条或多条转隐患。 | 将风险管控要求转为日常检查动作，避免问题遗漏。 |
| 隐患治理与督办 | 支持巡检转入、随手拍、集团监督检查和专业检查等来源；办理隐患登记、受理、分派整改人、整改反馈、复查、关闭；逾期生成督办建议，重大隐患具备升级确认和重点提示。 | 每条隐患均有责任人、期限、处理记录和关闭结论。 |
| 特殊作业管控 | 覆盖动火、高处、临时用电、有限空间；填写作业风险分析，校验人员资格，完成系统内置 BPM 审批、监护确认、现场执行、延期和归档。 | 用作业票将资格、风险、审批和现场执行串联，降低高风险作业失控风险。 |
| 管理驾驶舱 | 汇总风险等级、风险点分布、隐患状态、逾期督办、特殊作业和组织对比等指标，支持按组织和时间筛选并下钻到业务单据。 | 管理人员可快速识别高风险区域和待处理事项。 |
| 移动现场端 | 提供待办、巡检、随手拍、监护确认、作业过程、签到、消息、我的；未完成作业票地图仅展示当前未完成作业票。 | 现场人员可在移动端完成必要操作，减少回到 PC 录入的等待。 |
| 培训记录与证书 | 查询外部培训中心同步的培训记录；维护证书台账、临期提醒和换证；在特殊作业申请时校验相关资格。 | 防止无有效资格人员参与特殊作业。 |
| 安全知识库 | 分类管理法律法规和安全制度，支持目录浏览、关键字检索、原始文件查看和内容查询。 | 现场人员可快速查阅适用制度和规定。 |
| 应急管理 | 管理应急预案台账、版本、适用组织、原始文件和内容检索。 | 保证应急预案可查、版本明确、现场可用。 |
| 相关方管理 | 按维护单位建立相关方公司台账；维护现场人员与人员证书图片/PDF；登记人员违章；同一人员第 3 次违章后自动标记黑名单；集团、公司安全管理人员可跨单位查看。 | 建立可追溯的相关方基础台账和人员违章标记，不产生准入或业务拦截。 |

### 4.3 关键业务规则

1. 风险点以整个版本为审批对象，危险源不独立审批；一般/低风险经作业区负责人、二级单位安全管理人员审核后生效，较大/重大风险还须经二级单位领导批准。
2. 风险点退回后统一由班组长修改并重新提交，重新从作业区负责人审核开始。
3. 风险点责任信息采用责任岗位，不在风险点编辑中维护公共措施责任人或三级管控责任。
4. 巡检计划的周期决定生效开始/结束日期、自动派发时间及周/月执行规则；计划产生任务，巡检任务页面不再提供独立“临时下发”逻辑。
5. 班组任务由首位领取人锁定；班组长可按权限解锁或转交，并可标记未检及填写原因。
6. 巡检检查项的说明与照片分字段保存；检查结果仅为“合格”“不合格”。不合格项未转隐患前，在任务页面保留“转隐患”入口。
7. 巡检转隐患时，隐患标题默认取巡检检查项的说明；位置、发现人、发现时间、来源任务和现场照片自动带入，办理人可补充完善。
8. 隐患等级仅分“一般隐患”“重大隐患”。专业检查提交后直接形成已闭环台账，仅允许录入和查看本专业部门记录。
9. 特殊作业超时采用延期方式处理；一级动火每次延期最多 8 小时。

## 五、功能及界面设计

### 5.1 整体界面框架

PC 端采用“顶部全局栏 + 左侧一级模块导航 + 页面内容区”的业务系统布局。顶部展示系统名称、当前组织、待办消息和当前用户；左侧按业务模块分组；内容区采用“面包屑/页面标题 + 页签 + 筛选区 + 列表或工作区 + 详情抽屉/弹窗”的形式。

同一模块内优先通过页签组织关联业务，减少过深菜单和无意义跳转。列表页用于筛选、查询、批量操作和状态查看；详情页用于办理、查看流程与历史；新增、编辑、受理、转隐患等采用弹窗或侧边抽屉，并在成功后刷新对应列表状态。

### 5.2 PC 端模块页面

| 模块 | 建议页签/页面 | 主要界面与交互 |
|---|---|---|
| 目标职责 | 机构和职责、组织人员、用户信息、角色管理、角色数据权限、安全履职 | 左侧组织树与右侧列表联动；人员来自 OA 只读选择；角色与岗位映射支持搜索、筛选和查看授权范围。 |
| 风险管理 | 风险总览、风险台账、风险四色图、风险告知、变更复评、历史版本 | 风险台账展示风险点、位置、等级、状态和责任岗位；详情采用步骤式编辑，支持新增多个危险源、逐条评价和措施填写；审批状态点击可查看 BPM 流程摘要。 |
| 巡检任务管理 | 巡检总览、检查标准、巡检计划、巡检任务、执行结果、统计 | 检查标准按检查项维护必拍规则；计划页集中配置类型、周期、执行班组、检查范围和引用标准；任务页展示领取、执行、未检原因及转隐患状态。 |

| 相关方管理 | 相关方台账、人员与证书、违章记录、黑名单 | 按维护单位筛选；证书支持图片/PDF 附件；第三次违章后自动显示黑名单标记。 |
| 管理驾驶舱 | 综合看板、风险态势、隐患督办、特殊作业、组织对比 | 顶部设置组织和时间筛选；指标卡、趋势图、分布图、风险地图及待办列表均可下钻到对应业务单据。 |
| 培训记录与证书 | 培训记录、证书台账、临期预警、换证记录 | 培训记录只读；证书页支持按人员、工种、有效状态筛选，并从作业票资格校验结果跳转查看。 |
| 安全知识库 | 分类目录、文件列表、内容检索 | 左侧目录、右侧文件列表和预览区；搜索结果定位到文件和命中内容。 |
| 应急管理 | 预案台账、版本记录、文件查看、内容检索 | 以预案卡片/列表展示适用组织、版本和有效状态；详情查看原始文件和历史版本。 |

### 5.3 移动现场端

移动端采用底部四栏：**首页、任务、现场、我的**。

- **首页：** 展示本人待办、待执行巡检、待监护作业、待整改事项和消息提醒。
- **任务：** 按待办、巡检、作业、整改分类展示，可直接进入办理页。
- **现场：** 提供巡检执行、随手拍、监护确认、作业过程记录、签到和未完成作业票地图入口。
- **我的：** 展示当前人员、组织、岗位、消息和常用入口。

移动巡检采用逐项卡片交互：选择合格/不合格、填写说明、按检查标准要求上传照片；提交后如存在未转隐患的不合格项，直接进入转隐患弹窗，支持单选或多选转入。侧边抽屉可点击遮罩关闭，业务新增和审批类弹窗不允许点击遮罩误关闭。

## 六、研发实施验收重点

1. 以真实角色完成风险点新增、多个危险源录入、审批生效、变更复评的完整演示。
2. 以已发布检查标准创建巡检计划，自动生成任务，完成领取、现场执行和未检原因记录。
3. 对巡检不合格项完成单条、批量转隐患，验证自动带入字段、受理分派、整改反馈、复查关闭和逾期督办建议。
4. 完成四类特殊作业从申请到归档的操作，并验证资格校验、审批、监护、延期规则。
5. 核验 OA 人员同步、平台角色映射、系统内置 BPM、企业微信待办消息之间的边界和异常处理。
6. 核验驾驶舱、风险台账、隐患台账、作业票和移动端展示的数据范围符合登录人员权限。

7. 验证相关方公司、人员证书、违章登记和三次违章自动黑名单标记；集团、公司安全管理人员可跨单位查看，黑名单不触发业务限制。
