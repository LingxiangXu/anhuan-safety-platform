# 6. 巡检任务管理模块 PRD

## 6.1 模块概述

### 6.1.1 模块定位

巡检任务管理模块承接风险管理模块中的风险措施关联，将检查项目编制为日常岗位巡检和监督检查两类计划，按组织、区域、执行班组和频次自动生成任务，支持 PC 端计划管理和移动端现场执行。巡检发现异常时，必须逐条转为隐患，形成“风险参考→巡检检查→现场发现→隐患治理”的闭环。

本模块采用“组织基础角色 + 业务流程岗位”授权：班组长负责关联风险点、编制和发布检查标准，并负责有因转交或标记未检；执行班组成员负责领取和执行，作业区负责人负责巡检计划配置。任务领取后不提供解锁并退回公共任务池的操作。平台管理员不得代办领取或执行。

### 6.1.2 模块组成

| 序号 | 子模块 | 核心职责 | 面向角色 |
|---|---|---|---|
| 1 | 检查标准 | 关联风险点，维护检查内容、照片要求、版本和变更次数 | 班组长 |
| 2 | 巡检计划 | 编制日常岗位巡检或监督检查的周期、范围、执行班组和生效日期 | 作业区负责人 |
| 3 | 任务生成与领取 | 统一从巡检计划自动生成班组任务，班组内首人领取后锁定 | 系统自动 / 执行班组成员 |
| 4 | 现场执行 | 按检查内容逐条检查、逐条拍照、备注、定位和异常上报 | 巡检人员 / 岗位人员 |
| 5 | 结果复核 | 查看完成率、漏检项、异常项和任务闭环 | 安全管理人员 / 车间负责人 |

### 6.1.3 模块内部关系

```
风险管控措施
      │ 关联并带出初始内容
      ▼
检查标准（班组长维护独立版本） → 巡检计划 → 生成整班任务 → 首人领取锁定
                                      │
                                      ▼
                              移动端逐项执行
                                      │
                              ┌───────┴────────┐
                              ▼                ▼
                         合格记录        不合格/异常（可多项）
                                               │
                                               ▼
                                   按检查项分别生成隐患
```

### 6.1.4 与其他模块的依赖关系

| 依赖模块 | 依赖内容 | 依赖方式 |
|---|---|---|
| 风险管理 | 风险点、危险源、管控措施、检查输出标记 | 关联并带出初始检查内容，不反向修改风险数据 |
| 组织权限 | OA 同步的组织、部门、岗位、人员和在职状态；平台配置班组及业务角色映射 | 控制计划范围、领取资格和任务可见性 |
| 隐患治理 | 隐患登记、责任分派、整改和复查 | 不合格项一键创建隐患 |
| 移动现场 | 任务列表、拍照、定位、离线缓存 | 现场执行入口 |
| 企业微信待办 | 待领取、已领取、执行中、逾期、异常和复查提醒 | 平台生成待办后统一推送企业微信，点击进入任务详情 |

### 6.1.5 核心业务流转图

```mermaid
flowchart LR
  risk["已生效风险措施"] --> standard["逐条编制检查标准"]
  standard --> publish["发布检查标准版本"]
  publish --> plan["创建巡检计划"]
  plan --> team["绑定自动线组或制模组"]
  team --> generate["按周期自动生成任务"]
  generate --> claim["班组成员领取"]
  claim --> lock["首人领取后锁定"]
  lock --> execute["现场逐项检查"]
  execute --> pass["合格记录"]
  execute --> fail["不合格检查项"]
  fail --> pending["待转隐患"]
  pending --> hazard["单选或多选逐条转隐患"]
  lock --> transfer["班组长有因转交"]
  transfer --> execute
  pass --> complete["提交任务完成"]
  hazard --> complete
```

说明：检查项是否必拍由检查标准逐条配置；不设置“临时下发”入口。

### 6.2.2a inspection_plan_standard — 计划引用检查标准

| 字段 | 类型 | 必填 | 说明 |

| id | bigint PK | ✓ | 主键 |

| standard_version_id | bigint FK | ✓ | 被引用的已发布检查标准版本 |

## 6.3 状态流转

```
计划：DRAFT → PUBLISHED → SUSPENDED/EXPIRED（停用必须填写原因）
任务：PENDING（待班组成员领取） → CLAIMED（首人领取后锁定） → IN_PROGRESS → COMPLETED
           │                         │                  │
           │                         └─班组长有因转交──┘
           └────────────────────────────→ OVERDUE → SUPPLEMENTARY_CHECK / UNINSPECTED（未检必须填写原因）
结果：未填写 → 合格 / 不合格
不合格 → 待转隐患 → 单选/多选创建隐患 → 已转隐患 → 隐患治理流程

巡检项目：DRAFT → PUBLISHED → RETIRED；负责人修改已发布项目时生成新版本，不覆盖历史任务使用的版本。
```

## 6.4 功能清单

| 编号 | 功能点 | 操作 | 说明 | 权限 |
|---|---|---|---|---|
| F-INSP-01 | 巡检标准维护 | 增删改查 | 维护项目、标准、来源风险点和判定方式 | 安全管理人员 |
| F-INSP-02 | 关联风险措施生成项目 | 导入/编辑 | 每个被选风险点分别生成一份巡检标准草稿，不合并风险点；已有草稿不覆盖。负责人可调整检查表述、频次、必检和证据要求 | 安全管理人员 / 负责人 |
| F-INSP-03 | 创建巡检计划 | 新增 | 设置日常岗位巡检或监督检查；周期紧随计划类型选择，自动派发时间及星期/每月第几日等派生参数集中配置；生效开始/结束字段按周期切换维度：每日为日期、每周为周边界日期、每月为月份、每季度为季度首月；执行班组先于检查范围选择，检查范围默认由执行班组带出且允许修改；引用已发布检查标准时展示风险点位置；实时展示首次生成日期和预计任务数量；可同时引用多份已发布检查标准，不配置可领取岗位 | 作业区负责人 |
| F-INSP-04 | 发布/停用计划 | 操作 | 发布后按周期自动生成任务；停用必须填写原因且不影响历史结果 | 安全管理人员 |
| F-INSP-05 | 自动生成任务 | 周期规则 | 已发布计划按周期自动生成任务，同一计划同一周期幂等；不提供人工“生成任务”或“临时下发”入口 | 系统自动 |
| F-INSP-06 | 领取/转交 | 操作 | 首位班组成员领取后任务锁定且不能解锁退回任务池；班组长仅可填写原因后转交，记录前后责任人 | 班组成员 / 班组长 |
| F-INSP-07 | 现场执行 | PC/移动端 | 按检查内容逐条选择合格或不合格；说明和照片为两个独立字段，说明始终可填写，不合格时必填；照片按每条检查标准的必拍配置校验 | 巡检人员 |
| F-INSP-08 | 不合格转隐患 | 操作 | 提交结果后关闭执行弹框并重新查询任务；存在不合格且未转隐患项时自动打开与任务列表“转隐患（N）”相同的弹框，不存在时回到任务列表。弹框只展示待转项，支持勾选单条或多条，每项分别创建隐患并带入标题、位置、风险来源、检查项和现场照片 | 巡检人员 |
| F-INSP-09 | 任务复核 | 查看/操作 | 查看漏检、不合格和隐患转化情况 | 安全管理人员 |
| F-INSP-10 | 统计分析 | 查看 | 按组织、计划、人员、周期统计完成率、漏检率和不合格率 | 管理层 |

## 6.5 业务规则

| 编号 | 规则 |
|---|---|
| BR-INSP-01 | 检查项目可以关联风险管控措施并带出初始内容；负责人修改的是巡检项目独立版本，不得反向修改已生效风险措施 |
| BR-INSP-01a | 一个检查项目下录入多条检查内容时，计划与任务必须按检查内容逐条展开；每条检查内容生成一条独立任务检查项，不得用分号等方式合并为一项 |
| BR-INSP-01b | 是否必拍由检查标准中每条检查内容人工配置，默认不强制；计划和任务原样带入，现场执行仅对标记为必拍的检查项校验现场照片 |
| BR-INSP-01c | 在检查标准页同时勾选多个风险点时，系统按风险点分别生成独立草稿；两个风险点不得合并为一份草稿，已存在草稿的风险点只提示继续编辑，不覆盖现有内容 |
| BR-INSP-02 | 日常岗位巡检和监督检查是一期两类计划；监督检查可通过子类型标记专项、节假日、季节性或复查场景 |
| BR-INSP-03 | 巡检计划必须绑定执行班组；已发布计划按周期自动生成任务，同一计划同一周期只能生成一份任务，重复生成必须幂等 |
| BR-INSP-03c | 周期紧随计划类型选择。每日按开始/结束日期逐日生成；每周按开始/结束周边界和所选星期生成；每月按开始/结束月份及所选日期生成；每季度按开始/结束季度（季度首月）每三个月生成。周期变化时同步切换生效字段维度、标签和校验提示；周期或生效区间变化时实时重算首次日期和预计数量；有效期内无生成日期时阻止保存 |
| BR-INSP-03b | 创建一份巡检计划时可勾选多份已发布检查标准；这些标准中的检查内容合并进入同一计划，但每条检查内容仍是独立任务项。该计划每个周期只生成一份任务，不按标准数量拆成多份任务 |
| BR-INSP-03a | 任务初始为待领取；首位有权限的班组成员领取后锁定执行人。领取后不提供解锁或退回公共任务池；班组长可因请假、换班、设备/区域调整等填写原因后转交，记录原领取人、新领取人、操作人和时间 |
| BR-INSP-04 | 一线岗位必检项目建议控制在 10 项以内；每条任务项均必须选择合格或不合格，存在未填写结果时不得提交任务 |
| BR-INSP-05 | 每条检查内容独立生成任务检查项；检查结果只允许合格、不合格；说明和照片必须分字段保存；不合格项必须填写说明，配置为必拍时必须上传照片 |
| BR-INSP-06 | 每条不合格检查结果分别生成一条关联隐患；隐患标题等于对应检查项的巡检说明；同一任务有 N 条不合格项时应生成 N 条隐患，并按“任务 + 检查项”防重。提交结果弹框和任务列表入口共用同一待转清单，支持单选或多选；关闭弹框不会丢失待转状态 |
| BR-INSP-07 | GPS 默认作为现场证据记录；是否阻断提交由计划配置，不以不确定的定位误差直接否定任务 |
| BR-INSP-08 | 任务逾期只改变任务状态，不自动伪造检查结果；逾期不计入按时完成率。补检或管理员关闭必须填写原因，未检关闭必须留痕 |
| BR-INSP-09 | 巡检任务完成不代表隐患闭环，隐患独立走受理、整改、复查流程 |
| BR-INSP-10 | 打开现场执行页面不立即改变任务状态；完成现场位置确认后任务才从“已领取”进入“执行中”，列表必须同步刷新 |
| BR-INSP-11 | 巡检任务显示执行班组和实际领取人，不显示或配置“可领取岗位”。任务下发到整个班组，班组内首位领取人员成为实际执行人并锁定；领取人必须是 OA 同步的在职班组成员 |
| BR-INSP-11a | 班组长保留有因转交和标记未检两类操作，均必须填写原因并记录操作人和时间；转交还需记录原领取人和新领取人。系统不提供解锁操作 |
| BR-INSP-11b | 工部或作业区未划分班组时，平台按该组织创建一个默认执行班组；默认班组只用于任务领取和统计，不反向新增 OA 组织 |
| BR-INSP-12 | 已产生历史任务的巡检计划只允许停用，不允许删除；停用不影响历史任务、结果和隐患来源关系 |
| BR-INSP-13 | 停用计划必须填写停用原因；停用不撤销已生成任务，已生成任务仍按原计划版本完成或按授权规则标记未检 |

## 6.8 非功能与验收

- 任务列表 P95 ≤ 1 秒；移动端提交单项结果 ≤ 800ms。
- 网络中断时保留未提交结果，恢复网络后可重试，不重复建单。
- 必须完成“班组长关联风险点→调整检查内容并发布版本→显示版本和变更次数→作业区负责人创建计划并绑定执行班组→周期与生效日期联动并预览任务次数→系统自动生成整班任务→班组内首人领取锁定→班组长有因转交/标记未检→现场位置确认→逐条选择合格/不合格并分别填写说明、照片→提交后关闭执行弹框并重新查询→存在待转项时自动打开转隐患弹框→选择单条或多条不合格项转隐患→关闭弹框后从任务列表继续处理剩余待转项→隐患台账逐条显示位置”的浏览器验收。
- 必须验证停用计划填写原因、未检任务填写原因，以及计划停用不改变历史任务和结果。
- 必须验证同时选择两个风险点时分别生成两份检查标准草稿；创建一份计划并同时引用两份已发布标准时，该计划每周期只生成一份任务，任务内检查项数量等于两份标准独立检查内容之和。
- 必须验证计划类型下方优先显示周期；切换每日、每周、每月、每季度时，生效起止字段分别切换为日期、周边界日期、月份、季度首月；计划周期或生效区间变化时首次生成日期和预计任务数实时重算；有效期内没有任何生成日期时阻止保存。
- 必须验证同一任务部分不合格项转隐患后，任务仍为已完成并显示剩余“待转隐患 N 条”；已转换项显示隐患编号且不能重复转换，全部转换后“转隐患”入口消失。
- 当前项目状态：数据库和后端业务尚待建设；原演示系统已有移动巡检和随手拍交互参考。
