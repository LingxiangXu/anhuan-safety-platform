# 风险管理原型 PRD 一致性改造任务书

日期：2026-08-05  
范围：仅完善安全管理平台 PC 端“风险管理”模块，不修改巡检、隐患、特殊作业和驾驶舱独立业务页面。  
目标：完整演示“创建辨识任务 → 划分风险点 → 辨识危险源 → 每条危险源独立评价并审批 → 制定措施与责任 → 风险点版本审核批准 → 生效发布 → 台账/四色图/告知卡 → 变更复评 → 历史版本”。

## 1. 最新业务规则

1. 一个风险点可以包含多条危险源。
2. 每条危险源独立填写辨识信息、LEC/直接判定评价、管控措施和责任。
3. 每条危险源评价必须独立触发审批，禁止批量批准、越过审批或由评价人自审自批。
4. 危险源评价状态：草稿 → 待审批 → 已批准；退回后为已退回，可修改后重新提交。
5. 危险源评价审批记录必须保存评价快照、提交人、审批人、意见、时间和状态变化。
6. 风险版本仍按整个风险点保存。全部危险源评价独立批准且措施、责任完整后，才能提交整个风险点版本。
7. 风险点版本状态：草稿 → 待部门初审 → 待安全审核 → 待公司批准 → 当前生效；任一节点可退回。
8. 台账、四色图、公告栏和岗位风险告知卡只读取同一风险点的当前生效版本。
9. 已生效评价和版本只读；修改必须发起风险变更或人工复评，复制整个风险点快照形成新草稿。
10. 风险告知卡只在线查看，不提供打印、PDF或二维码。

## 2. 当前必须删除或修正的错误逻辑

1. 删除提交预览中的“批准全部危险源”按钮和 `approveAll()` 逻辑。
2. “保存评价”只能保存草稿，不得自动等同于提交审批。
3. 增加“提交评价审批”，提交后锁定当前评价字段并生成独立审批待办。
4. 增加评价审批详情、批准、退回、退回原因校验、重新提交和审批历史。
5. 评价人和审批人相同时必须阻断审批，并明确提示切换到授权审批角色。
6. 修复危险源实际为“待审核”却显示为“待评价”的状态错误。
7. 修复台账危险源明细进入指定危险源时未携带 `wb=1`、未进入工作台的问题。
8. 工作台不得固定使用 `R-001`；必须根据 URL 中的风险点和危险源参数加载。
9. 发布风险版本不得把全部危险源评价强制改成“已批准”。
10. 最高等级必须从当前风险点全部已批准危险源中计算，不得硬编码为较大。

## 3. 页面级完善范围

### 3.1 风险总览

- KPI：风险点总数、重大/较大风险、待评价审批、待版本审批、管控措施总数。
- KPI 点击进入对应列表并带入筛选条件。
- 台账一览显示危险源数量、当前生效最高等级、版本和状态。
- 业务入口可进入辨识任务、评价审批、四色图、风险告知和变更复评。
- 移除风险告知入口上的打印图标和任何打印暗示。

### 3.2 风险台账与风险点建档

- 支持编号、名称、组织、位置、类别、等级、状态和版本筛选，并提供重置。
- 新建风险点表单至少包含名称、类别、组织、区域/位置、风险点总责任人和建档原因；必填校验和成功反馈真实可演示。
- 风险点详情抽屉展示全部危险源、每条评价状态、评价结果、措施数量、责任和审批记录入口。
- 草稿风险点可编辑/删除；已生效风险点不得物理删除，只能发起变更/复评或停用。
- “进入危险源评价”必须准确打开对应风险点、对应危险源和正确工作台步骤。
- 台账只把当前生效版本作为正式发布口径；无生效版本的数据明确标记为草稿/审批中。

### 3.3 辨识任务列表与新建任务

- 支持创建任务：任务类型、范围、负责人、参与人员、计划日期、触发原因。
- 显示草稿、辨识中、待部门初审、待安全审核、待公司批准、已生效、已退回等状态。
- 每种状态只显示当前角色可执行的动作：编辑、继续辨识、提交、初审、审核、批准、退回、查看。
- 任务页内部提供“危险源评价审批待办”和“风险点版本审批待办”入口，不必增加新的平台一级菜单。

### 3.4 辨识与评价工作台

六步结构保留，但每一步必须可录入、校验和回显：

1. 风险点信息：名称、类别、组织、位置、责任主体、任务/版本信息。
2. 危险源辨识：多条危险源列表；新增、编辑、删除、切换；字段包含类别、描述、事故类型、后果、影响范围和总体责任人。
3. 危险源评价：LEC与直接判定；保存草稿、提交审批、查看审批历史；待审批/已批准状态下字段只读；退回后可修改重提。
4. 管控措施：按当前危险源独立新增、编辑、删除；字段包含措施类别、内容、责任部门、责任人、监督部门、岗位执行人、频次、证据要求、实施状态、输出巡检、输出特殊作业。
5. 责任确认：逐条展示当前危险源和措施责任完整度；缺失字段可直接定位编辑，不允许只显示静态说明。
6. 提交预览：按危险源逐条显示辨识、评价审批、措施、责任是否完成；有未批准评价或责任缺失时阻断；全部通过后只能“提交风险点版本初审”，不能直接发布。

### 3.5 危险源评价独立审批

- 待办列表字段：评价编号、风险点、危险源、L/E/C/D、等级、评价人、提交时间、当前状态、当前审批人、操作。
- 详情显示提交时评价快照、直接判定依据和历史动作。
- 授权审批人可以批准或退回；退回必须填写原因。
- 评价人不可审批自己的评价；无权限用户只能查看。
- 批准后危险源状态为“已批准”，返回工作台后可继续完善措施和责任。
- 退回后工作台展示退回原因，并允许评价人修改后重新提交。

### 3.6 风险点版本审批与生效

- 全部危险源评价批准后，发起人提交整个风险点版本初审。
- 部门初审、安全审核、公司批准逐级推进；每个节点支持退回并保存意见。
- 公司批准后版本变为当前生效，旧版本归档，任务完成。
- 禁止从工作台直接点击“发布正式版本”绕过审批。
- 审批详情显示版本快照范围、危险源数量、最高等级、措施数量和审批时间线。

### 3.7 风险四色图

- 只展示当前生效风险点，颜色由最高等级自动映射。
- 点击标记打开对应风险点详情和危险源列表。
- 提供授权用户“维护定位”操作：区域、楼层、X/Y坐标；保存后页面标记发生可见变化。
- 提供组织、等级筛选和图例；无坐标风险点有明确待维护列表。

### 3.8 安全风险公告栏和岗位风险告知卡

- 支持按组织、岗位和风险点筛选当前生效版本。
- 公告栏汇总风险点、危险源、等级、主要措施、责任人和生效版本。
- 岗位告知卡在线查看全部危险源和主要措施，记录查看人、查看时间和版本。
- 不出现打印、PDF、二维码或导出按钮。

### 3.9 变更、人工复评和历史版本

- 增加“发起风险变更/人工复评”按钮和表单：风险点、触发类型、变更原因、影响范围、计划完成时间。
- 发起后复制整个风险点当前版本，形成新版本草稿和辨识任务，并提供进入工作台入口。
- 版本列表显示草稿、审批中、当前生效、已归档状态。
- 历史版本详情为只读快照；版本对比至少展示风险点字段、危险源增删、L/E/C/D、等级、措施和责任差异。
- 新版本未生效前，台账、四色图和告知卡继续使用旧版本。

## 4. 数据与权限要求

- 在统一 mock store 中维护评价审批记录、评价待办、风险点版本审批记录和角色权限，不在页面内硬编码成功状态。
- 使用现有角色切换演示权限；至少保证评价人与审批人分离，可用“公司安环”和“集团安环”分别演示发起与审批。
- 所有新增、编辑、提交、审批、退回、发布、发起复评操作写入统一日志并持久化到现有 localStorage mock 状态。
- 刷新页面后状态应保持。
- 不修改其他业务模块的数据结构，除非为了保持已有风险措施输出关系兼容。

## 6. 验收要求

1. 六个风险左侧页签全部可访问，无空白页和控制台错误。
2. 所有可见按钮都有可见结果：页面跳转、抽屉、弹窗、状态变化、校验提示或明确禁用原因。
3. 完整跑通两条危险源分别评价、分别提交、分别审批，其中至少一条先退回再重新提交批准。
4. 评价人无法自审自批；不存在“批准全部危险源”按钮。
5. 全部评价批准前不能提交风险点版本；版本未完成三级审批前不能生效发布。
6. 风险点版本生效后，台账、四色图、公告栏、告知卡同时切换到相同版本。
7. 发起人工复评后生成包含全部危险源、评价、措施和责任的整点草稿版本。
8. 浏览器宽度 1366、高度 768 下关键字段、状态、按钮不被遮挡。
9. 运行现有按钮审计或等价检查，风险模块所有按钮无未定义函数、无死链。
10. 完成后提交修改清单、验证步骤、已知限制和待主代理确认事项。
