# 安全管理平台原型与 PRD 一致性复核记录

> 历史复核快照：本文件只记录 2026-08-13 当时的检查结果，不作为当前业务规则依据。文中“较大/重大风险走 OA、生成审批 PDF”等旧口径已失效；当前规则以最新业务确认清单、整体 PRD 和现行原型为准。

复核日期：2026-08-13

## 本轮结论

已按当时业务规则修正原型和 8 份 Markdown PRD。风险、巡检、隐患、特殊作业、PC 待办与移动现场端的关键状态和权限保持一致；本轮未使用或修改 Figma。

## 已修正内容

- 风险点整体审批；危险源分别评价、填写措施和责任，不设置危险源独立审批。
- 重大、较大风险生成风险点审批 PDF 后从安全管理平台发起 OA；一般、低风险使用平台内审批。
- 巡检任务由计划按周期生成并绑定班组，首人领取锁定；班组长有因解锁、转交或标记未检并留痕。
- 集团监督检查 OA 批准后，由被检查二级单位安全管理人员受理分派；集团专业检查提交后形成同专业闭环台账。
- 作业票超时必须申请延期；延期申请核对人员、监护人、地点、环境和措施，批准后原确认失效并重新监护确认。
- PC 与移动端使用同一业务待办对象；首页指标可下钻到对应筛选结果。
- 主要页面不再显示机加工旧场景、旧风险编号和旧人员。

- JavaScript 语法检查通过。
- 浏览器核心交互验收：35 项通过，0 项失败。

- 8 份 PRD 均为有效 UTF-8 Markdown，未发现本轮规则冲突。
