# 安全管理平台整体原型 · 演示说明

## 1. 入口与运行

- PC 入口：`workbench.html`（统一待办工作台）或 `index.html`（管理驾驶舱）；侧栏可进入工作台、目标职责、风险管理、巡检任务、隐患治理与督办、特殊作业管控、培训与证书、应急管理和安全知识库。
- 移动入口：`mobile.html?view=home`。推荐使用 390×844，底部导航固定为首页 / 任务 / 现场 / 消息 / 我的。
- 运行时请从本目录启动任意静态 HTTP 服务，再通过服务地址访问；所有资源均为相对路径、本地 SVG/CSS/JS，未依赖外网字体、地图或公共脚本资源。原型不支持直接双击作为生产系统，也不代表真实接口、权限或持久化。

## 2. 演示角色与组织

- 集团监督检查（演示人员待配置）：发起集团监督检查、查看集团范围和授权发起/关闭隐患督办。
- 二级单位安全管理（王欣宇）：风险审核、随手拍/集团监督检查隐患受理分派和岗位安全职责维护的演示视角。
- 作业区负责人（演示人员待配置）：风险审核、巡检计划维护、巡检隐患受理和整改复查的演示视角。
- 平台管理员/岗位映射管理员：查看企业微信组织人员同步结果，维护平台用户、业务岗位映射、安全业务角色和角色数据权限；不得代办业务审批。
- 自动线组班组长（张青）：巡检执行、整改反馈、作业申请与现场操作。
- 组织范围：太重集团 → 太原重工股份有限公司 → 铸锻件分公司 → 造型作业区（自动线组、制模组）。顶栏角色菜单可切换演示视角。

## 3. 推荐演示路线

1. 驾驶舱切换组织/时间范围，查看风险点、隐患、巡检、活跃作业、证书临期、班组参与率 KPI；点击 KPI 下钻到带筛选的业务列表，点击全屏验证壳层。
2. 风险管理 → 风险台账：由班组长新建风险点并添加多条危险源，各危险源分别完成 LEC/直接判定和五类管控措施，危险源不单独审批。整个风险点版本统一提交平台内置审核：先经作业区负责人、二级单位安全管理人员审核；一般/低风险至此生效，较大/重大风险继续由二级单位领导审批后生效。任一节点退回班组长，修改重提后从作业区负责人重新开始；风险不接入 OA。生效后，台账、四色图和在线告知卡统一引用该版本。
3. 班组长在巡检管理 → 检查标准页面引用已生效风险点的管控措施，编辑并发布独立检查项目版本；页面展示标准版本和变更次数，编辑不会反向覆盖风险措施。巡检计划只绑定执行班组并按周期自动生成任务；任务下发至整个班组，班组内首位领取人成为实际执行人并锁定。班组长可填写原因后解锁、转交或标记未检；没有真实班组的工部/作业区使用平台默认执行班组。
4. 巡检任务现场执行：先校验模拟位置，逐项判定；不合格必须写说明，是否必拍由检查标准逐条配置。每一条不合格检查项分别生成一条关联隐患，隐患可由作业区负责人受理并分派，也可填写原因后不受理关闭；受理后进入整改情况说明 + 整改后照片 → 作业区负责人复查 → 闭环。
5. 隐患治理：台账展示 `INSPECTION`（巡检发现）、`MOBILE_REPORT`（随手拍）、`PROFESSIONAL_DEPT_CHECK`（集团专业检查）、`HSE_SUPERVISION`（集团监督检查）四类来源。受理时整改要求可使用并维护常用语。集团专业检查使用独立的完整新增页面登记发现、整改、闭环和考核字段，提交后直接形成已闭环台账，不展示 OA，只允许同专业部门查看；集团监督检查由平台发起 OA，台账“审批中”跳转外部 OA，批准回传考核人和金额后进入受理整改。逾期项只生成督办建议，授权确认后才创建独立督办单。
6. 特殊作业：一期仅动火、高处、临时用电、有限空间。作业票初审和延期均使用安全管理平台内置审批，完整展示节点、审批人、意见和时间，审批待办推送企业微信；作业人员与多名监护人分别选择，监护确认全部通过，并完成签到、位置校验和开工照片后才能开工。作业中可补充过程照片，超时延期批准前阻断作业；一级动火每次延期最多 8 小时。支持暂停/恢复/完工/验收/归档。“审批规则”可演示四类×四级矩阵配置，但正式岗位矩阵仍须业务签字确认；集团监督检查不作为作业审批节点。
7. 移动现场端：属于一期正式上线范围。企业微信是组织、部门、人员、岗位的唯一数据源和正式移动入口；平台只映射安全业务角色。首页将未读待办消息置于快捷入口前，平台待办统一推送企业微信并携带业务入口，OA 内部节点待办不重复生成。现场端支持巡检、随手拍、整改/复查、监护确认、作业过程、签到、消息和未完成作业票地图。
8. 培训与证书：培训记录由培训中心同步并在平台只读查询；证书人员从企业微信组织人员选择，支持证书新增、编辑、换证、临期和过期筛选。驾驶舱“证书临期”可下钻证书台账；特殊作业资格阻断可跳转证书管理，换证后返回作业票重新校验。
9. 目标职责：依次查看“组织机构维护、组织人员维护、用户信息维护、角色管理、角色数据权限、岗位安全职责清单”。组织、人员、原始岗位和在职状态只读模拟企业微信同步；平台管理员在用户信息维护中分别配置业务岗位映射和用户角色映射。角色数据权限页按角色维护默认范围，不显示人员列；确需跨组织查看时单独新增带原因和有效期的人员例外授权。二级单位安全管理人员按“责任组织＋安全业务岗位”维护岗位安全职责，页面显示当前承接人员和匹配状态，可查看人员绑定；未匹配时可返回用户信息维护补充映射，编辑职责时生成历史版本并保存当时人员快照。

10. 安全知识库与应急管理：安全知识库按“法律法规、公司安全制度”分类管理 PDF，支持目录筛选、查看原文件和正文检索；应急管理独立维护应急预案，支持目录分类、查看原文件和预案内容检索。原型只演示目录、详情和命中定位，真实 PDF 解析、OCR 和检索服务仍待建设。

11. 工作台：切换演示角色后查看该角色可办理的风险、巡检、隐患和特殊作业待办，点击“办理”进入对应页面。PC 工作台、移动任务中心与企业微信推送使用同一业务对象；消息已读不等于业务完成。

未完成作业票地图目前只验证“仅展示未完成作业票”的筛选与入口，图中点位为示意坐标，不代表真实 GIS 定位；正式能力需要厂区底图和位置坐标资料。

隐患正式等级只保留一般隐患、重大隐患两级；登记后受理前可显示未定级，受理定级时只能二选一。重大隐患显示升级确认和重点管控提示。

## 4. 验证脚本

在本目录执行：

PowerShell 先准备全局 Puppeteer 模块：

```powershell
$env:NODE_PATH = npm root -g
```

如果 Puppeteer 未自动找到浏览器，再按当前电脑实际安装位置注入可执行文件路径（占位符不应原样提交）：

```powershell
$env:PUPPETEER_EXECUTABLE_PATH = '<本机 Chromium/Chrome 可执行文件路径>'
```

然后运行两套验收脚本：

```powershell
node _verify.js
node _interact.js
node _button-audit.js
```

`_button-audit.js` 检查全部页面按钮是否绑定、inline handler 是否暴露、跳转文件是否存在，以及通用抽屉是否具备可见状态；`_verify.js` 和 `_interact.js` 会自建临时 HTTP 服务，捕获页面错误、资源 404、横向溢出，并验证弹窗/抽屉真实可见与关键状态流转，生成 1366×768 与 390×844 截图到运行目录下的 `_verify/`。交付代码只包含相对资源和本地 mock，不应填写真实账号、密钥或业务数据。
